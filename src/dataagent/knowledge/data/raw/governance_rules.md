# 数据治理规范（原始 wiki 摘录）

> 非结构化原始语料。由 `dataagent.knowledge.build` 拆解为 `data/built/policies.yaml`。
> 治理助手 Agent 逐条执行这些规则，输出问题清单（规则号 + 级别 + 证据 + 修复建议）。

## G01 分区过滤缺失

- 严重级别：P0
- 适用对象：sql
- 检查逻辑：查询 dwd_ 或 dws_ 层表时，where 子句中未出现分区字段 date
- 修复建议：在 where 中补充 date 范围条件，避免全表扫描
- 负责人：数据平台-治理组

## G02 禁止 SELECT *

- 严重级别：P1
- 适用对象：sql
- 检查逻辑：select 列表中出现星号
- 修复建议：显式列出所需字段，避免上游加列导致下游血缘失真
- 负责人：数据平台-治理组

## G03 敏感字段未脱敏

- 严重级别：P0
- 适用对象：sql
- 检查逻辑：出现 up_id、user_id、phone、device_id 等敏感字段且未包裹脱敏函数
- 修复建议：改用 mask_up_id(up_id) 等平台脱敏函数后再输出
- 负责人：数据安全组

## G04 指标口径硬编码

- 严重级别：P1
- 适用对象：sql
- 检查逻辑：在 SQL 中直接书写比率计算（含除号且分子分母来自明细列）而未引用指标平台
- 修复建议：改为引用指标平台已注册指标，避免口径分叉
- 负责人：数据平台-治理组

## G05 表命名不规范

- 严重级别：P2
- 适用对象：table
- 检查逻辑：表名不以 ods_、dwd_、dws_、ads_、dim_ 前缀开头，或包含大写字母
- 修复建议：按《数仓分层命名规范》重命名并同步血缘
- 负责人：数据平台-治理组

## G06 字段命名不规范

- 严重级别：P2
- 适用对象：sql
- 检查逻辑：select 或 where 中出现驼峰命名的字段
- 修复建议：统一改为小写下划线命名
- 负责人：数据平台-治理组

## G07 跨层依赖

- 严重级别：P1
- 适用对象：sql
- 检查逻辑：ads_ 层表在 from 或 join 中直接引用 dwd_ 层表
- 修复建议：改为引用 dws_ 层汇总表，保证分层清晰
- 负责人：数据平台-治理组

## G08 JOIN 缺少关联条件

- 严重级别：P0
- 适用对象：sql
- 检查逻辑：出现 join 关键字但缺少 on 子句
- 修复建议：补充 on 关联条件，避免笛卡尔积
- 负责人：数据平台-治理组

## G09 无上限的全表导出

- 严重级别：P1
- 适用对象：sql
- 检查逻辑：查询明细层表且既无分区过滤也无 limit 子句
- 修复建议：补充分区条件或 limit，控制扫描量
- 负责人：数据平台-治理组

## G10 指标重复建设

- 严重级别：P2
- 适用对象：metric
- 检查逻辑：新建指标的口径定义与已注册指标的相似度超过 90%
- 修复建议：复用已有指标，或在指标平台提交合并申请
- 负责人：数据平台-治理组
